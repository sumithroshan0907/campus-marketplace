1. EXECUTIVE SUMMARY
--------------------------------------------------------------------------------
Campus Marketplace is a full-featured, multi-tier web application specifically 
engineered for university and college student communities. It empowers verified 
students to buy, sell, negotiate, and exchange academic textbooks, electronics, 
hostel supplies, and bicycles within a safe, peer-reviewed ecosystem.

Key Value Highlights:
- Closed/Verified Campus Community: Configurable email domain restrictions.
- Dynamic Multi-Role System: Distinct student and administrator permissions.
- Full E-Commerce Cycle: Listings, multi-image galleries, price negotiation 
  (offers & counter-offers), direct real-time chat, wishlists, and peer ratings.
- Zero-Setup Resilience: Can operate with MySQL 8 or auto-seeded in-memory H2.
- Cloud-Native Readiness: Docker containerization for Render; optimized Vite 
  production build with SPA rewrite rules for Vercel/Render static hosting.

2.2. Resolving the "Can't Upload New Login Credentials" Defect
- Problem: The user reported inability to register or submit new credentials.
  Root-cause analysis uncovered four distinct bottlenecks:
  1. Hardcoded College Email Restriction: AuthService.java strictly required emails 
     to end with "@college.edu". Any user registering with "@gmail.com", "@yahoo.com", 
     or personal emails was rejected with a 400 Bad Request error.
  2. Frontend Crash on Error: In Register.jsx, the catch block used:
     err.response?.data?.message || err.response?.data?.errors ? Object.values(err.response.data.errors)...
     Because "||" has higher precedence than "? :", when the backend returned a 400 
     message, JavaScript executed Object.values(undefined), triggering an uncaught 
     "TypeError: Cannot convert undefined or null to object" that froze the UI.
  3. Mandatory Student ID: RegisterRequest.java enforced @NotBlank on studentId, 
     rejecting registrations without academic roll numbers.
  4. Missing Password Management: The application had no mechanism for existing 
     users to update their password or login credentials from their profile.
- Solution:
  1. Updated AuthService.java: Permitted any valid email during development/demo 
     mode while still accepting "@college.edu", ".edu", and ".ac.in" domains.
  2. Auto-generated studentId ("STU" + timestamp) if omitted, and made it optional 
     in RegisterRequest.java.
  3. Set "emailVerified = true" on registration so new accounts can log in immediately.
  4. Fixed the operator precedence bug in Register.jsx to safely extract server errors.
  5. Implemented a complete credential update flow in AuthService.java, 
     UserUpdateRequest.java, and UserController.java (verifying current password 
     before applying a new BCrypt-hashed password).
  6. Added a "Update Login Credentials / Password" section to the Profile Settings 
     tab in Profile.jsx.
  7. Successfully validated end-to-end registration, login, password update, and 
     re-login with new credentials via automated API tests.

6. SECURITY, AUTHENTICATION & ACCESS CONTROL
--------------------------------------------------------------------------------
- Stateless JWT Security:
  Authentication produces an HMAC-SHA512 signed token (24-hour expiration).
  On every subsequent API request, JwtAuthFilter parses the "Authorization: Bearer <token>" 
  header, verifies the signature, and establishes Spring Security's SecurityContext.
- Password Encryption:
  Passwords are encrypted using BCrypt with automatic salting before persisting.
  Raw passwords never touch logs or database records.
- Role-Based Access Control (RBAC):
  End-points under /api/admin/** require the "ADMIN" role authority.
  Student profile mutations enforce ownership checks (e.g. only the listing owner 
  can update or delete an item; only the receiver can accept offers).
- Account State Defense:
  Blocked users ("accountActive == false") are rejected at login with HTTP 403 Forbidden.
- Cross-Site Scripting (XSS) & Injection Defense:
  React automatically escapes values in JSX.
  Spring Data JPA uses parameterized queries, preventing SQL injection.
